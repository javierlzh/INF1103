1. Section 2.1 The Problem
Question: The business now wants a 5% student discount. 
Without the Strategy pattern, which class and method must 
change? After you complete Section 2, answer the same question 
again for your Strategy version.

Prediction:
Without Strategy, I expect Order.calculate_total() to need another discount
branch. With Strategy, I expect the 5% calculation to belong in

Actual result:
Reviewing Order.calculate_total() confirmed that it delegates to

2. Section 2.3 User a strategy in Order
Question: Create an order whose lines add up to 250. What will 
calculate_total() return with BulkDiscount(200,20)? What if you 
then call set_discount(Percentage(10)) on the same order? Write 
both answers down, then run your code and check.

Prediction:
Reading 200 as an order-value threshold, I would expect 250 - 20 = 230.
After switching the same order to a 10% percentage discount, I expect 225.

Actual result:
I created one product priced at 50 and added five units to an order, giving
an order subtotal of 250. With BulkDiscount(200, 20), calculate_total()
returned 230. Calling set_discount(PercentageDiscount(10)) on that same
order then returned 225.0. BulkDiscount compares the order subtotal with
its monetary threshold, including equality: a total of 200 becomes 180,
while 199.99 stays unchanged. PercentageDiscount is the class name in this
project.

3. Section 2.4 Extend without modifying
Question:  Look back at Lab 8. Which relationship best 
describes Order and DiscountStrategy: association, aggregation 
or composition? Hint: is a discount part of an order, or 
something the order uses? Could two orders share the same 
PercentageDiscount object? Write your answer and a multiplicity
for each end, then check it against your code. 

Prediction:
I expect association because Order uses a discount algorithm. Two orders
should be able to reference the same PercentageDiscount object. Each Order
uses exactly 1 DiscountStrategy, and each strategy can be used by 0..* Orders.

Actual result:
Two Orders were created with the same PercentageDiscount(10) object.
Their stored strategy references were identical when compared using is.
Orders with subtotals of 100 and 200 returned 90 and 180 respectively.
Replacing the first order's strategy with PercentageDiscount(5) changed its
total to 95 while the second order still returned 180.
The relationship is association. The multiplicity at the DiscountStrategy end
is 1 and at the Order end is 0..*. Omitting a constructor strategy creates a
NoDiscount object, so every constructed order still has a strategy.

5. Section 3.3 Who knows about what?
Question: Suppose a new BundleProduct type is added. How many 
places in your code would need to change before you added the 
factory, and how many after? Count them, then explain why the 
factory still breaks OCP and why that is acceptable here. 
 

Prediction:
I expect the factory to concentrate the constructor-selection changes in
ProductFactory.create(). Before the factory, extending several separate
creation callers would require editing each caller. The new BundleProduct
class, input fields and loading format may also need implementation.

Actual result:
I checked Git commit bac1222, immediately before the factory commit.
It contains 6 explicit physical/digital constructor calls across 3 caller
files: 2 in lsp_demo.py, 2 in polymorphism_demo.py, and 2 in the relationship
test setup. Extending all of those example callers to offer a third type
would distribute the creation edits across those 3 files.
In the current design, constructor selection is centralized in 1 existing
method, ProductFactory.create(). Existing callers can request a product type
through that method.
For full BundleProduct support in the current menu and JSON loader, at least
3 existing files need review: product_factory.py for construction, ui.py for
Bundle-specific input, and persistence.py for required record fields.
New record fields would also require updating product_data.py. The new class
and its tests are additional work in either design.
The factory still needs a new branch when a product type is added, so it is
not fully closed to modification under OCP. This simple factory is acceptable
for the lab because construction decisions have a clear central location and
the example has a small set of known product types.

6. Section 4 Add validation
Question: Think back to the Lab 8 LSP discussion. If Product 
validates that stock cannot go negative, should DigitalProduct 
be allowed to skip or change that rule? Why? 
 

Prediction:
I expect DigitalProduct to preserve Product's nonnegative-stock rule.
Accepting negative stock in a subclass would break the contract relied on
by code using Product references and would violate LSP.

Actual result:
I created a physical product and a digital product, each with stock 5,
then called update_stock(-1) on each. Both raised:
ValueError: Stock cannot be negative.
Both still had stock 5 after rejection. Both subclasses inherit the same
Product.update_stock() validation and call the parent constructor for initial
stock validation. A subclass must preserve this contract to satisfy LSP.

8. Section 5.2 Loading products from a file
Question: Before running, write down how many products will 
load, which messages will print, and in what order. Then rename 
products.csv and predict again: which of except, else and 
finally will run? 
 

Prediction:
I expect 3 products to load into an empty inventory. The service row
should report an unknown type, and the Office Chair row should report its
invalid price. Then I expect the loaded count and final message.
After renaming the file, I expect FileNotFoundError to be caught, else to be
skipped, and finally to print the finishing message.

Actual result:
With the supplied products.csv and an empty Inventory, the exact messages
were printed in this order:
Skipping row 4: Unknown product type: service
Skipping row 5: could not convert string to float: 'abc'
3 products loaded.
Load attempt finished.
Desk Lamp (P001), Photo Editor (D001), and Monitor Stand (P003) loaded.
The outer else block ran. Each invalid row was caught by its own inner
except ValueError, and subsequent rows continued to load. finally ran last.
I then renamed a temporary copy of the CSV and tried its original path.
The missing-file message included that original path, followed by:
Load attempt finished.
For a run using the relative path products.csv, the missing-file messages are:
Products file not found: products.csv
Load attempt finished.
The outer except FileNotFoundError and finally blocks run in this case.
The else block is skipped, so no loaded-count message is printed.
The loader supplies 0.0 placeholders for weight and download size because
the supplied CSV omits those fields.
